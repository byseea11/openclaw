## 1. 当前整体状态

当前可以把 Feishu Task Wiki 理解为一条已经能跑通的三阶段主链：

1. **Layer 1：task binding**
2. **Layer 2：source session + verified session_event**
3. **Layer 3：session_wiki / index / task_wiki**

这三层现在都已经有真实实现，而且已经接到了：

- `extensions/feishu-task-wiki/openclaw-lark/`

也就是说，当前不是“只有 repo 内抽象模型改了”，而是：

```text
task 绑定
→ source session
→ verified session_event
→ session_wiki.md / index.md / task_wiki.md
→ lint / forgetting / log.md
```

这条链现在已经在本地可运行，并且已经用真实 `lark-cli` 样本验证过。

## 2. 当前已经完成的能力

### 2.1 Layer 1：Task Binding

当前第一阶段已经完成：

- canonical `task` 与 `source binding` 分离
- `task_id` 采用显式任务号语义，例如：
  - `task:FEISHU-231`
- 不同 source 只要识别到同一个 `taskKey`，会映射到同一个 canonical task
- binding 查询优先级已经固定：
  - `thread_id`
  - `root_id`
  - `chat_id`
  - `source_id`
- chat 初始化后，后续长出 thread/root 时会补绑定，不覆盖原 chat binding
- runtime 已经按 task-first when bound 进入：
  - task session key
  - task queue key

- `extensions/feishu-task-wiki/openclaw-lark/src/task-banding/task-binding.ts`
- `extensions/feishu-task-wiki/openclaw-lark/src/task-banding/task-binding-store.js`
- `extensions/feishu-task-wiki/openclaw-lark/src/task-banding/task-routing.ts`

runtime 接入点：

- `extensions/feishu-task-wiki/openclaw-lark/src/channel/event-handlers.js`

### 2.2 Layer 2：Event 主线

当前第二阶段已经完成：

  - `chat`
  - `thread`
  - `comment`
  - `doc` 当前只保留结构接口，未接 live runtime
- source session 采用稳定容器模型：
  - `source_session_id = task_id + "::" + source_scope`
- ingest 采用递增追加，不会每次新建平行 session
- `thread / comment` 的 Core 语义已经稳定：

## 5. 当前还缺失的部分

虽然三阶段主链已经跑通，但还保留少量待补项。

### 5.1 Layer 1 还缺的部分

- `taskKey` 识别仍偏保守，当前主锚点还是显式编号：
  - `FEISHU-231`
  - `飞书-231`
- 还没有单独的人为绑定管理入口：
  - 例如显式把新 source 手动绑到既有 task
- `doc / comment` 在 binding 层虽然结构支持，但还没有像 chat/thread 一样做完整 live 验证

### 5.2 Layer 2 还缺的部分

- `comment` 路径已接入，但还没做真实 live comment 样本验收
- `doc` 目前只保留接口和数据结构，未接正文 live runtime
- compaction 现在是固定窗口策略，后续需要根据真实群流量继续调参
- `session-stream.json` 还是实现辅助文件，是否保留为长期正式契约还没最终定
- `candidate_events.jsonl` 的人工 review / retry 流程还没继续做

### 5.3 Layer 3 还缺的部分

- `views/*.md` 这一层当前明确不做
- 当前 block 级增量更新外部效果已经对齐，但内部实现仍是：
  - marker + sidecar patch
  - 不是更重的 AST 级 patch
- `manual_review` 这类人工复核流在设计里留了位置，但还没有完整接上
- `comment` source 虽然能进入第三层结构，但还没用真实 comment 样本做完整 wiki 验收
