第一层当前实现链路

Graph Index 的运行时输入已经收口为 transcript span。每轮消息不会直接写入业务语义表， 而是由 handleGraphAfterTurn 先做 L0 signal detection： 检查消息、tool result、任务号、状态词、owner、blocked、done、due 等信号，只有命中后才进入 graph 更新队列。

  • projection_inbox 是待处理 span 队列。 它保存 source、first/last entry、entries_json、dirty_reason、signal_strength、strong_event。 目的不是存最终语义，而是把“哪些 session transcript span 还没有投影成 evidence/event”稳定落盘， 让后续 drain 不依赖 host 重新回读历史 transcript。
  • source_projection_state 是每个 source 一行的恢复状态机。 它记录 covered_until_entry_id、dirty_since_entry_id、last_projected_at、projection_version、status。 这张表保证进程重启、失败、并发 drain 后仍能知道这个 session 当前是 clean、dirty、draining 还是 failed。
  • 不能只靠一个队列顺序抽取：队列只能说明“有哪些 span 待处理”，不能可靠表达 “这个 session 已经覆盖到哪里、是否正在 drain、失败后从哪里恢复、recall 前是否必须补齐”。 因此 inbox 负责 pending work，state 负责 source-level cursor。
  • drainPendingGraphUpdates 是唯一批量抽取入口。 它按 source 汇总 pending inbox，解析 entries_json，渲染为 transcript batch，调用 extractor， 再进入 canonicalizeV2 和 persistSemanticBatchV2。
  • drain 触发点包括 recall 前同步补齐、strong_event 异步 drain、dirty_threshold、idle、beforeCompaction。 beforeCompaction 会强制把即将压缩的 transcript span 先入 inbox，再同步 drain，避免 compaction 后丢失细粒度事件。
更新流：afterTurn / beforeCompaction → L0 检测 → projection_inbox + source_projection_state → drain 批量抽取 → V2 semantic persist → cursor advanced。

第二层当前实现链路

第二层已经不再以旧 event_records / entity_states 为主语义层，而是固定为 V2 六张表。 其中核心事实链是三张表：证据、事件类型注册、事件账本；图谱视图是三张派生表：workflow state、entity、edge。

evidence_records 证据层。由 transcript batch 生成，保存 content_text、content_json、source_locator_json。 使用 evidence_fingerprint 幂等去重，运行时不再接收 flush graph 输入。
event_type_registry 受控事件类型注册表。当前固定 owner_changed、stage_changed、approval_status_updated、 blocked、unblocked、next_action_set。
event_records_v2 唯一事实层。append-only，通过 event_fingerprint 去重。 subject_ref / actor_ref / object_ref 都是 typed business key。
workflow_state_view_v2 当前 workflow 状态视图。只能由 event slot patch/upsert 得出， 维护 owner、stage、approval、blocker、next_action、slot_versions_json。
graph_entities_v2 typed business object anchor。由 evidence/event 驱动 upsert， 用于后续 query resolve entity_ref。
graph_edges_v2 当前关系视图。由 event 派生，支持 upsert/close， 只表达当前 active relation，完整历史回到 event_records_v2。
  • 创建图时先写 evidence_records 和 event_records_v2，再由 projector 统一生成 workflow state、entities、edges。
  • state 不能被 evidence 直接写入，只能由 event 按槽位投影； edge 不能被 evidence 直接写入，只能由 event 派生； entity 由 event/evidence upsert。
  • 更新不是覆盖事实。event append-only，state 是当前视图，edge 是当前关系视图。 关系失效时 close edge，状态槽位由更晚的 event_fingerprint / occurred_at 版本覆盖。
  • 旧 semantic 表已经退出主路径；历史旧事件只通过 migration 转成 V2 evidence/event， 然后重放 projector 生成 V2 state/entity/edge。

第三层当前实现链路

检索层不再走旧的 event FTS + entity_states。当前 memory_search 的 graph branch 会先检查当前 session 是否还有 pending projection；如果有，会先同步 drainPendingGraphUpdates(reason="recall")， 再调用 searchGraphV2。

  • classifyQueryV2 将问题分成 state、why、timeline、list_relation。 默认是 state；包含“为什么 / blocked / blocker / 原因”走 why；包含“历史 / timeline / changed”走 timeline； 包含“哪些 / 列出 / related / 关系”走 list_relation。
  • resolveEntityRefV2 先识别显式任务号和审批号， 再查 graph_entities_v2 的 entity_ref、canonical_name、alias_json， 解析出 task、approval、person、blocker。
  • state 查询读取 workflow_state_view_v2， 返回当前 owner、stage、approval、blocker、next_action，并可通过 last_event_id 回到 event/evidence。
  • why 查询读取 workflow 的 slot_versions_json， 找到导致当前 blocker、approval_status、stage、next_action 的 event， 再 join evidence_records 给出证据片段。
  • timeline 查询按 subject_ref / object_ref / related_refs_json 查 event_records_v2，按 occurred_at 排序，再补 evidence。
  • list_relation 查询分两类：列表类直接扫 workflow_state_view_v2； 关系类走 graph_edges_v2 并回连 graph_entities_v2。
淘汰与清理：projection_inbox 的 row drain 后标记 drained_at，不再参与 pending； source_projection_state 推进 covered_until；recent_graph_hits 记录召回结果并按 TTL 清理； event/evidence 作为事实层不主动淘汰，state/edge 是可重建的当前视图。
存储 第一层保存 pending transcript span 和 source cursor； 第二层保存 V2 evidence/event 事实和由 event 派生的当前视图。
更新 新消息先过 L0 detector，命中后入 inbox； drain 批量抽取并事务化写入 V2，再推进 cursor。
检索 recall 前先补齐 pending drain； query 先分类、再 resolve entity_ref、最后按 state/why/timeline/list_relation 路由。
淘汰 pending span drain 后软清理；usage hit 按 TTL 清理； evidence/event 保留为事实层，state/edge 可由 event 重建。
